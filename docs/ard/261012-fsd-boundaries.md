# FSDと公開ファイル

状態：採用。利用者との一問一答で決定。

## 決定

Nuxtの薄いルートとFSDの画面実装を分離し、app → pages → widgets → features → entities → sharedの依存方向を守る。サーバー実装はserverに分離する。

スライスごとに公開ファイルを明示し、越境参照はそのファイルへ直接importする。同一スライス内は相対importを使う。バレルエクスポートと同一レイヤーの別スライス参照は禁止する。Nuxtの自動importも無効にする。

## 理由と代替案

依存関係をコード上に明示し、静的に検査できるようにする。当初提案したindex.ts経由の再エクスポートは、利用者のバレルエクスポートを避ける希望により採用しない。Nuxt自動importに任せる方式も採用しない。

## 影響

公開ファイルの変更は依存側の契約変更としてレビューする。配置・依存方向の独自チェックをOxlintと併用する。
