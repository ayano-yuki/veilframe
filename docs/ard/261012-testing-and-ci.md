# カバレッジとUI検証

状態：採用。利用者との一問一答で決定。

## 決定

Vitest、Nuxt Test Utils、Playwrightを使う。アプリの行・文・関数・分岐100%をCIの必須条件にする。通常CIでは外部DRMサービスと再生をテスト用実装に差し替える。実際のWidevine再生とキャプチャ結果はWindows・AndroidのChrome実機で検証する。

UI関連のファイル・設定・依存変更時にPC幅とモバイル幅で3画面、記録詳細、削除確認、再生主要状態、エラーを撮影する。GitHub Actions成果物を同じPRコメントからリンクする。

## 理由と代替案

カバレッジを単なる目標にする案は採用しない。外部サービスの稼働やDRM非対応CI環境を通常テストの成否に含めず、失敗条件を再現して検証する。画像の直接表示には外部公開先が必要となるため成果物へのリンクを選択した。

## 影響

カバレッジ100%は実機の保護動作を保証しない。テストと実機検証の結果を区別する。GitHubリポジトリ未指定のため、コメント投稿の実運用確認は接続後に行う。
