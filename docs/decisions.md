# 合意済みの仕様・開発方針

この文書は実装前の一問一答で合意した内容を記録する。未決定事項を実装側の推測で補わず、変更は利用者に確認する。実装・実機検証・CIの完了を示す文書ではない。

## 目的と公開範囲

- NuxtベースのDRM・保護描画・キャプチャ挙動検証アプリ。名称はveilframe。
- 初期対象はShaka Player、Widevine、WindowsとAndroidのChrome。
- ローカル開発後、Vercelでログインなしで公開する。現時点では公開操作やGitHubリポジトリへの接続は行わない。
- 公開環境では公開テスト素材だけを利用可能にする。独自接続と秘密の認証情報はローカル環境限定。
- 公開素材はShaka Player公式デモから利用条件と接続可否を確認して選ぶ。提供元・利用条件・設定を文書化する。
- 実際のスクリーンショットで映像が黒くなることは保証しない。Windows・Androidの実機で確認する。

## 再生・接続

- 通常DRM再生とハードウェア保護要求の2モード。
- 保護モードは映像・音声の両方にHW_SECURE_ALLを要求する。非対応時は失敗として表示し、自動で要件を緩和しない。
- 独自接続は環境変数を初期値とし、画面で動画URLと許可済み接続先を変更できる。
- ライセンス取得はNuxtサーバー経由。許可したURLから選択する。URL・認証ヘッダーはサーバー側で管理する。
- Nuxt runtime configで公開設定とサーバー専用設定を分離する。ブラウザには必要な識別情報だけ渡す。
- 画面で変更した独自接続設定は永続保存しない。
- ライセンス転送は15秒でタイムアウトし、自動再試行しない。

## 記録・画像

- IndexedDBとidbを使い、端末・ブラウザ内で保存する。サーバーには送信しない。
- 記録項目：日時、素材名、接続先識別名、再生モード、要求保護要件、対応確認・再生結果、環境情報、キャプチャ方法、目視結果、メモ、画像。
- 目視結果：映像が写る、黒くなる、その他、未確認。
- 環境情報は取得可能な情報だけ自動入力し、利用者がOS・Chromeのバージョン・端末名・キャプチャ方法を確認・補完する。不明値を推測しない。
- 動画URLとライセンス認証情報を検証記録・エクスポートに含めない。
- fflateでJSONと個別画像をZIPにまとめ、インポートにも対応する。
- 重複IDは既存記録を保持してスキップし、取り込み件数とスキップ件数を表示する。
- PNG・JPEG・WebPのみ。1画像10MB、1記録5画像まで。
- インポート上限：ZIP100MB、展開後200MB、1,000記録。不正形式や超過を取り込み前に拒否する。
- 記録単位で削除し、添付画像も削除する。実行前に確認する。

## UI

- 日本語UI・日本語ドキュメント。コードの識別子は英語。
- 再生・検証、記録一覧・詳細、接続設定の3画面。公開環境では独自接続設定を表示しない。
- ダーク基調、動画プレイヤー中心。利用者の要望は「AIぽさがないデザイン」。
- VueコンポーネントとCSSで独自実装し、UIコンポーネントライブラリは使わない。
- 共通CSS変数・リセット・基本スタイルはshared、各コンポーネントはstyle scoped。

## 設計・静的検査

- FSDベース。依存方向はapp、pages、widgets、features、entities、sharedの上位から下位へ。
- Nuxtルート定義は薄い入口とし、画面実装はFSD側に置く。
- 動画再生・ライセンス取得・記録保存をインターフェイスで分離し、実装レビューを行う。
- serverはAPI入口・転送処理・接続先設定・外部通信を分離する。ブラウザ専用コードへの依存を禁止する。
- 同じスライス内は相対import。他スライス・レイヤーはエイリアスで明示された公開ファイルに直接importする。
- バレルエクスポート、内部ファイルへの越境参照、同一レイヤーの別スライス依存は禁止する。
- VueファイルはPascalCase.vue、その他のファイル・ディレクトリはkebab-case。関数・変数はcamelCase、型・インターフェイスはPascalCase。Nuxt指定名の例外を文書化する。
- Oxlintと独自静的チェックを併用し、配置・命名・依存方向・APIの利用方法のガードレールを設ける。
- TypeScript strict、型チェック必須。anyと型チェック抑制は原則禁止。外部入力はZodで検証する。
- pnpmを採用。安定版・互換性を確認して正確な依存バージョンを固定し、Node.jsとpnpmも統一する。

## 検証・CI

- Vitest、Nuxt Test Utils、Playwrightを採用。
- アプリの実装コードは行・文・関数・分岐すべて100%カバレッジをCIの必須条件にする。設定・生成コード等の除外を文書化する。
- 単体・コンポーネントテストは対象に隣接する*.test.ts。E2E・撮影はtests/e2e、共有補助コードはtests/support。
- CIのUIテストはDRM再生をテスト用実装に差し替え、実際のWidevineは実機検証する。
- GitHub Actionsを作成する。GitHubリポジトリは後で指定する。
- 画面・コンポーネント・スタイル・UI関連設定・依存パッケージの変更時に撮影する。判定パスを文書化する。
- PC幅とAndroid相当のモバイル幅で3画面・記録詳細・削除確認・再生主要状態・エラー状態を撮影する。
- 画像はActions成果物に保存し、同じPRコメントにダウンロードリンクを更新する。

## 開発手順の管理

- AGENTS.mdに必須ルール、docsに仕様・設計理由、プロジェクト専用Skillにレビュー・検証手順を置く。
- 専用Skillはリポジトリ内skillsに配置し、AGENTS.mdから参照する。
- 未確定の技術選定もGrill-me形式で一問ずつ確認する。

## 追加の合意

- SSRを使用し、ブラウザ専用処理をクライアントに分離する。
- 条件変更で停止・破棄・結果リセットし、明示操作で再生する。
- 状態管理はPinia。プレイヤー・秘密情報をストアへ保持しない。
- 失敗・非対応も記録できる。キャプチャ未確認も許可する。
- 独自接続は既定無効・明示的な有効化が必要。Vercelでは拒否する。
- Prettierを使い整形検査を必須にする。
- 通常CIは外部DRM通信を差し替える。
- ライセンス転送のリダイレクトは拒否。要求・応答は各1 MiBまで。
- インポートは全件検証後に一括保存し、不正があれば何も保存しない。
- インターフェイスの契約・失敗・終了・競合・秘密情報・テスト実装の整合性をレビューする。
- 設計判断はdocs/ard/YYMMDD-kebab-case.mdに置き、既存の合意も整理する。
- Nuxt自動importを無効にする。
- コンポーネントテストはHappy DOM、計測はV8、IndexedDBテストはfake-indexeddb。
- AndroidからのローカルHTTPSはmkcert方式。
- Node.jsはローカル・CIで24.16.0、Vercelは24.16.0以上25未満を許可し実バージョンを記録する。

## Brave対応の合意

- Windows・AndroidのBraveをChromeと同じ検証対象へ追加する。
- ブラウザの種類とバージョンを別項目にし、種類はChrome・Brave・未確認から手動選択する。
- 既存記録と旧ZIPを読み込めるようにする。旧種類は推測せず未確認とする。
- CIは既存のChromium UIテストを維持する。Brave実体のWidevine再生とOS撮影はWindows・Androidで手動検証する。

## PlayReady対応の合意

- Windowsのハードウェア保護検証にEdge＋PlayReadyを追加する。
- PlayReady保護モードは映像にSL3000を要求し、音声は既定条件を使う。非対応時は停止し、通常モードへフォールバックしない。
- DRM方式はWidevine／PlayReadyから手動選択する。ブラウザ情報から自動変更しない。
- 記録にDRM方式を追加し、HW_SECURE_ALLとSL3000を区別する。ブラウザ種類にEdgeを追加する。
- 旧記録・旧ZIPをWidevine記録として読み込み、新規ZIPはversion 3にする。
